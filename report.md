# Сбор и поиск мест

## 1. Данные

Снимок собран из OpenStreetMap через Nominatim по семи категориям: кафе, рестораны, музеи, парки, театры, библиотеки и кинотеатры. Для запроса задан московский `viewbox`, отдельный `User-Agent` и пауза между обращениями к API.

Обычный запуск читает `places_raw.csv` и не зависит от сети. Новый сбор выполняется только при явном `refresh=True`. После удаления объектов Московской области, административных районов, попавших в выдачу парков, и повторов осталось 63 места.

В исходном снимке сохраняются идентификатор OSM, название, категория, адрес, координаты, часы работы, кухня, доступность, наружная посадка, интернет, ссылки, лицензия и исходные дополнительные теги.

## 2. Семантические признаки

Для семи категорий задана одна таблица профилей. В каждой строке находятся:

- типы опыта;
- атмосферы;
- контексты посещения;
- подходящее время;
- русские термины для поиска.

Например, кафе получает признаки еды, работы, уютной атмосферы и посещения с друзьями. Парк получает прогулку, природу, спокойную атмосферу и семейный контекст.

`extract_features` берёт профиль категории и дополняет его фактическими OSM-тегами. Wi-Fi добавляет рабочий сценарий, наружная посадка — террасу и улицу, `wheelchair=yes` — доступность. В `feature_evidence` записывается источник каждого уточнения.

Бюджет остаётся `unknown`: в OSM нет достаточно полных цен, поэтому он не выводится из названия или категории. `metadata_completeness` показывает долю заполненных дополнительных полей.

Результат сохраняется в `places_enriched.csv`. Списочные поля записываются как JSON-массивы.

## 3. EDA

Ноутбук показывает распределение категорий, типов опыта, атмосфер и контекстов. Одно место может учитываться в нескольких семантических значениях.

Фактический состав выборки:

| Категория | Мест |
|---|---:|
| cafe | 10 |
| cinema | 9 |
| library | 10 |
| museum | 10 |
| park | 5 |
| restaurant | 10 |
| theatre | 9 |

Также отдельно считается заполненность часов работы, кухни, доступности, сайта, Wikidata и Wikipedia.

## 4. Поиск

Сравниваются два индекса без предобученных моделей.

`Metadata` использует название, категорию, кухню, район и адрес. Это базовый вариант, который показывает качество поиска только по исходным полям.

`Enriched` добавляет семантический профиль категории и признаки из OSM. Для обоих вариантов используется `FeatureUnion` из словного TF-IDF по униграммам и биграммам и символьного TF-IDF по последовательностям длиной 3–5. Символьные признаки уменьшают проблему разных окончаний русских слов.

Отдельного `parse_query` и словарей фраз для каждого тестового запроса нет. Запрос и описание места сравниваются в одном текстовом пространстве.

## 5. Оценка поиска

Подготовлены шесть запросов: кафе для работы, место для свидания, ужин с друзьями, семейная прогулка, тихое место и музей на выходные. Для оценки заранее указаны допустимые категории и обязательные семантические признаки.

На глубинах 5, 10 и 15 считаются Precision, Recall, MAP, nDCG, MRR и HitRate. Это позволяет отдельно увидеть точность первых результатов, полноту более длинной выдачи и качество порядка.

Ниже оставлены значения предыдущего запуска для `@5`. Расширенная таблица будет записана после следующего запуска ноутбука.

| Метод | Precision@5 | nDCG@5 |
|---|---:|---:|
| Metadata | 0.433 | 0.436 |
| Enriched | 1.000 | 1.000 |

Семантическое обогащение сильнее всего влияет на запросы без явного типа места: для свидания, семейной прогулки и тихого отдыха. Полная выдача сохраняется в `search_results_comparison.csv`.

Оценка остаётся sanity-check: эталонные признаки основаны на той же таблице категорий, которая используется при обогащении. Результат показывает согласованность пайплайна, но не заменяет независимую пользовательскую разметку.

## 6. Файлы

- `places_semantic_search.ipynb` — сбор, обогащение, EDA, поиск и оценка;
- `places_raw.csv` — воспроизводимый снимок OSM;
- `places_enriched.csv` — 63 места с семантическими признаками;
- `search_results_comparison.csv` — первые 15 результатов двух методов по шести запросам.

## 7. Ограничения

OSM-теги заполнены неравномерно и могут устаревать. Атмосфера и контекст являются prior категории, а не подтверждённым свойством конкретного места. В данных нет отзывов, рейтингов и надёжных цен, поэтому запрос «недорогое место» нельзя проверить полностью. Следующий шаг — добавить эти поля и собрать независимые оценки релевантности.
